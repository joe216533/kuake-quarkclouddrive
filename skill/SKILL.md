# 夸克资产操作

只做四件事：**上传、转存、下载、分享**。不承担搜索、整理、相册、AI 问答等其它功能。

## 0. 首次使用：安装与验证

```bash
node scripts/install.js
```

安装器会自动完成：查询官方当前版本 → 下载官方组件 → 抽取到 `runtime/` → 记录 SHA256 → 运行能力验证。

退出码含义：

| 退出码 | 含义 | 下一步 |
|-|-|-|
| 0 | 四项能力就绪 | 可直接使用 |
| 2 | 组件就绪，**账号未授权** | 执行第 1 节的授权流程 |
| 1 | 存在真实失败 | 按输出修正，不得声称安装成功 |

**不得只凭"文件已下载"或"命令能打印帮助"就判定安装成功。** 必须看到 `verify.js` 输出 0。

## 0.1 网络前提（实测必需）

夸克网盘对境外出口有风控。**走境外代理/VPN 时，上传与下载会出现 TLS 连接被断开**：

```text
[ERROR][DownloadStarter] Download failed: Client network socket disconnected before secure TLS connection was established
{"code":1007,"msg":"Client network socket disconnected before secure TLS connection was established"}
```

处理规则：

1. 执行夸克上传、转存、下载、分享前，先确认当前出口为**中国大陆 IP**；
2. 若使用代理/VPN，先切到国内直连（或将该域名加白名单直连），再执行；
3. 出现 `1007` 或上述 TLS 断开错误时，**先报告这是网络出口问题，不要重复重试**，也不要误判为账号或技能故障；
4. 浏览器自动化同样适用：操作夸克网页时必须国内直连。

实测对照：同一账号、同一文件，境外出口下载失败（1007）；切国内直连后 2 秒内完成，大小与 SHA256 均正确。

## 1. 账号授权（三步，不能省第二步）

**CLI 不会自动轮询授权结果。** 用户扫码后如果直接跑 verify，会返回 `-103 未登录`。必须自己再跑一次 login 换取 token。

```bash
# 第 1 次：取二维码/链接给用户
node runtime/quark-drive.cjs login --session-id <会话ID> --session-input "<用户原话>"

# 用户确认已扫码后：第 2 次 login，换取 token 并落盘
node runtime/quark-drive.cjs login --session-id <会话ID> --session-input "<用户原话>"
# 期望返回 code:0 且 status:confirmed

# 第 3 步：验证
node scripts/verify.js
```

把**二维码或授权链接**提供给用户，放在回复末尾，一句话说明要做什么。

**登录态位置因环境而异**（实测见过 `~/.quarkclouddrive/config.json`，也见过技能目录下 `workbuddy/config.json`）。不要写死路径，以 CLI 输出与实际检查为准；**该文件含 token，严禁随包分发或提交到代码仓库**。

### 1.1 沿用既有登录态时的验证边界

覆盖升级时如果保留了旧登录态（如 `workbuddy/config.json` 或 `~/.quarkclouddrive/config.json`），新版本会**直接通过 verify 而不触发扫码**。这是预期行为，但必须说清它能证明什么、不能证明什么：

| 情形 | 可以得出的结论 |
|-|-|
| 沿用旧 token，verify 通过 | 旧 token 当前有效，基础检查通过 |
| 本次重新扫码，verify 通过 | 本次授权流程完成，基础检查通过 |
| 真实业务操作通过 | 对应功能在当前账号与环境已实测可用 |
| 未做真实业务操作 | 对应业务权限**仍未验证** |

**两条禁令**：

- 不得把"沿用旧 token + verify 通过"表述为"授权已验证"或"业务权限已验证"；
- 不得把"重新扫码成功"当作全部业务权限齐全——重新授权只证明授权流程成功，上传/分享能否使用仍取决于账号权限。

按变更类型决定要不要实跑：仅改文档 → 只跑 verify；涉及授权方式、token/scope、上游 CLI 大版本、业务接口实现 → 必须实跑对应功能。

**规范**：

- 必须主动提供授权入口（二维码图或链接），不得只说"请自行授权"；
- 二维码/链接之后不再追加其它说明；
- 不得索取账号密码、短信验证码；
- 不得转到别的账号或读取、复制浏览器 cookies；
- 授权成功后在同一会话内继续，不得要求重复登录。

## 2. 上传

```bash
node runtime/quark-drive.cjs upload "<本地路径>" [--parent-fid <目录FID>] \
  --session-id <会话ID> --session-input "<用户原话>"
```

上传前必须确认：

1. 当前账号号码**以 `159` 开头**；
2. 该账号网盘内**存在 `来自：WorkBuddy` 正式资产目录结构**。

两项同时成立才允许上传。**不要求核验完整手机号**（平台脱敏）。

上传后必须回读：列出目标目录、确认文件数、大小一致，记录远端文件名与本地文件的对应关系。

**不得**因为"另一个账号已登录更方便"就换账号上传。

## 3. 转存（另存）

```bash
node runtime/quark-drive.cjs saveas --url "<分享链接>" [--to-pdir-path "<网盘目录路径>"] \
  --session-id <会话ID> --session-input "<用户原话>"
```

### 3.1 创建者本人分享：免转存直接下载例外

正常情况下，下载他人分享的文件，应先执行 saveas 转存，再执行 download 下载。但当当前账号下载的是自己创建的分享时，夸克可能禁止将该分享再次转存。此时应跳过转存，直接下载分享对应的文件。

**创建者例外的权威判据仅有以下两项**：

- 页面明确提示「该链接为本人发出，不支持保存」；
- `saveas` 返回错误码 `41017`，提示「用户禁止转存自己的分享」。

命中任意一项，即认定当前操作触发了创建者免转存例外：

- 停止重复转存尝试，跳过 `saveas`，直接执行 `download`（第 4 节）；
- 不要求核验手机号、不检查是否 159 开头、不要求凑齐多项证据；
- 在报告里写明命中的是哪一条原文；
- **本例外只免除转存，不免除下载与 SHA256 校验**。

未命中上述两项时，必须按正常流程转存，不得仅凭猜测认定为本人分享，也不得无限重复转存。

**明确禁止使用 `is_owner` 判定创建者身份**：

此前曾考虑用 `share-detail` 返回的 `is_owner` 字段区分本人分享与非本人分享，**真实业务测试已证伪该字段的判别能力**：

- 156 账号下载他人分享时，`is_owner` 返回 `0`；
- 159 账号下载自己创建的分享时，`is_owner` **仍返回 `0`**，随后 `saveas` 返回 `41017`，跳过转存直接下载成功（13,760 B，SHA256 一致）。

同一个值 `0` 同时出现在本人与非本人分享场景中，无法区分创建者身份。因此：

- 不得依据 `is_owner=0` 决定必须转存；
- 不得依据 `is_owner=1` 决定可以直接下载；
- 无论该字段返回 0、1 或其他值，均不得将其作为创建者识别、转存决策或直接下载决策的依据；
- 该字段可保留在原始接口记录中，但仅作为未验证信息，不参与业务决策。

本规则以页面明确提示和实际错误码为准，不得根据 `is_owner` 推断或覆盖实际结果。下载侧不核验手机号，不要求必须使用 159 账号。

## 4. 下载

```bash
node runtime/quark-drive.cjs download --fid <文件FID> --output-dir "<本地目录>" \
  --session-id <会话ID> --session-input "<用户原话>"
```

**以实际落盘为唯一完成依据。** 以下任一项都不算下载完成：点了下载、菜单关闭、页面显示文件、客户端已打开、口头声称。

### 4.1 下载失败升级顺序

```text
① 网页版单文件下载（顶部操作栏，非右键），观察 2 分钟
     ↓ 未启动
② 网页版多文件下载（仅单文件验证后）
     ↓ 未启动
③ 夸克客户端下载（需单独确认客户端登录态）
     ↓ 不可用
④ 报告【存在限制】，申请人工下载
```

判定"未启动"的可观察依据：无浏览器下载记录、无夸克传输任务、目标目录无文件、页面明确提示需客户端、或任务失败取消。

**不得连续重复点击下载**，避免产生重复任务。**不得改用其它网盘或第三方镜像。**

浏览器登录态 ≠ 客户端登录态，两者分别记录，不得相互推定。

## 5. 分享

```bash
node runtime/quark-drive.cjs share <FID1> [FID2 ...] --title "<标题>" \
  --url-type 1 --expired-type 1 \
  --session-id <会话ID> --session-input "<用户原话>"
```

分享链接按公司规范设置为「永久、无提取码」，但**不得对用户表述为现实中绝对永久**。

创建分享属于**上传侧操作**，必须满足第 2 节的两项账号判据。

## 6. 完整性校验（强制）

下载完成后必须逐项核对：

| 项 | 要求 |
|-|-|
| 文件数量 | 应有数与实际数一致 |
| 文件名 | 与远端清单一致，或说明映射关系 |
| 文件大小 | 逐字节比较 |
| SHA256 | 与 manifest 或可信基准一致 |
| 可读性 | 能正常打开/解析 |

**SHA256 只证明文件内容与基准一致，不证明账号身份、上传位置或分享权限。** 不得把 SHA256 通过表述为"资产安全已验证"。

基准缺失时，明确标注该项【未验证】，不得跳过。

## 7. 证据与状态

每次操作结束，按四态报告：**【已执行】/【已验证】/【未验证】/【存在限制】**。

- 只做了动作没验证 → 【已执行】
- 有可检查结果印证 → 【已验证】
- 没做或没法做 → 【未验证】
- 平台限制导致无法完成 → 【存在限制】，写明限制内容

**不得把"已执行"写成"已验证"，不得把计划写成结果。**

## 8.1 备份必须放在技能目录之外

**禁止**在技能目录内创建 `.backup/`、`old/`、`previous/`、`_bak/` 等备份目录。

原因（已实测）：打包脚本 `package_skill.py` 使用 `rglob('*')` 收集文件，**不做任何过滤**，技能目录内的备份会被原样打进下一个分发包，可能带出旧代码、旧配置甚至凭据。

正确做法：备份放到技能目录之外的固定位置（例如 `D:\备份\skills\`），并在文件名里带日期与版本。

发布前 `preflight.js` 会对包内隐藏目录与备份命名做拦截，但**拦截只是第二道防线，第一道是不要把备份放进技能目录**。

## 8.2 禁止事项

- 禁止在账号判据不满足时上传、建分享或维护 manifest；
- 禁止把创建者例外扩大成"任何账号都可以跳过转存"；
- 禁止为取 41017 而重复点击保存；
- 禁止用其它网盘或非正式来源替代；
- 禁止在未验证的情况下声称安装成功或下载完成；
- 禁止把本技能用于与四类资产操作无关的功能。
